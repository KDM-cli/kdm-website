  <action>
    Create `src/context/ProductContext.tsx` with:

    1. `import { createContext, useContext, type ReactNode } from "react"`
    2. `import type { ProductConfig } from "@/config/products/types"`
    3. `import { products, defaultProduct } from "@/config/products/index"`

    4. `const ProductContext = createContext<ProductConfig>(defaultProduct)`

    5. `function ProductProvider({ slug, children }: { slug?: string; children: ReactNode })`:
       - If `slug` is provided, look up via `products.find(p ⇒ p.slug === slug)` falling back to `defaultProduct`
       - If no slug, use `defaultProduct`
       - Wrap in `<ProductContext.Provider value={config}>`

    6. `export function useProduct(): ProductConfig`:
       - Calls `useContext(ProductContext)`
       - Returns the config (never undefined — the default is always set)
       - Convention: use `slug` prop approach so the parent route passes it based on URL matching. The slug comes from URL patterns (e.g., `/kdm/*` → slug="kdm", `/docker-guard/*` → slug="docker-guard", health/legal pages → no slug → default)

    Design choice: The provider accepts an explicit `slug` prop rather than using `useLocation` internally. This keeps the provider pure and avoids coupling it to router internals. The route layouts pass down their product slug.

    Do NOT add any router imports or hooks inside the provider.
    Do NOT add `displayName` or dev-only logging.
  </action>
